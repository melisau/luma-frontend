# Luma Frontend

Static single-page application (SPA) with the digital invitation view, guest interaction forms (RSVP, photos, messages), and admin panel. All persistent data is managed through the [luma-backend](https://github.com/melisau/luma-backend) API.

## Requirements

- Modern browser (Chrome, Firefox, Safari, Edge)
- Running Luma Backend instance
- HTTPS in production (required for QR and clipboard APIs)

## Local development

### Option A — Monorepo single port (recommended)

If the backend `.env` has `SERVE_FRONTEND=true`, no separate frontend server is needed:

```bash
cd ../luma-backend
uvicorn app.main:app --reload --host 0.0.0.0 --port 5500
```

Browser: http://localhost:5500/. The local `js/config.runtime.js` uses the same origin for the API on port 5500, avoiding conflicts with other applications running on port 8000.

### Option B — Separate static server

For this mode, replace the local same-origin override in `js/config.runtime.js` with the API address shown below, and start the backend separately on port 8000.

```bash
python3 -m http.server 5500
```

Set the separate API address in `js/config.runtime.js`:

```js
window.__LUMA_API_BASE__ = 'http://127.0.0.1:8000';
```

Backend `.env`:

```env
FRONTEND_ORIGINS=http://127.0.0.1:5500,http://localhost:5500
SERVE_FRONTEND=false
```

Browser: http://127.0.0.1:5500/

## Configuration

Script load order (`index.html`):

1. `config.runtime.js` — optional API override (generated by CI in production; same-origin override for local port 5500)
2. `config.js` — default logic

On port `5500`, the local `config.runtime.js` uses the same origin for the API. For a separate static server, set its API override explicitly as shown above.

### Backend environment variables

The frontend does not read env vars directly; these backend settings must align:

| Backend variable | Purpose |
|------------------|---------|
| `FRONTEND_ORIGINS` | CORS — add your frontend origin |
| `PUBLIC_BASE_URL` | Correct domain for QR codes and invite links |
| `SERVE_FRONTEND` | `true` → single port; `false` → separate CDN |

## Deployment

### Cloudflare Pages

1. Connect the `luma-frontend` GitHub repository.
2. Select no framework preset.
3. Set the production environment variable `LUMA_API_BASE` to the Koyeb URL, for example `https://luma-api-ORG.koyeb.app`.
4. Use this build command:

```bash
bash scripts/write-config.sh
```

5. Set the build output directory to `.`.
6. Keep the root directory empty because this repository already starts at the static site root.
7. `_redirects` routes `/e/*` to `index.html` for invitation and upload links.
8. After Pages creates the public URL, update these Koyeb variables and redeploy the API:

```env
SERVE_FRONTEND=false
FRONTEND_ORIGINS=https://app.example.com
PUBLIC_BASE_URL=https://app.example.com
```

Preview deployments may use a different Pages origin. Add only the origins that need API access; do not use wildcard production CORS.

### Manual production config

Set the API URL in `js/config.runtime.js` using `js/config.production.example.js` as a reference. Legacy `config.local.js` and `config.production.js` files are no longer loaded; move any custom API override into `config.runtime.js`. Do not commit a local machine address.

### URL routes

| Route | Description |
|-------|-------------|
| `/` | Admin panel (sign-in required) |
| `/e/{private_token}` | Guest invitation page |
| `/e/{private_token}/upload` | Direct photo upload |

## Admin panel

| Section | Function |
|---------|----------|
| **Dashboard** | RSVP stats, activity feed, personalized greeting |
| **Invitation editor** | Date, cover, music, text content |
| **Guests** | List, add, edit, delete |
| **Gallery** | Approve, hide, favorite photos |
| **Guestbook** | Approve, hide, delete messages |
| **QR Code** | Event-scoped upload QR |
| **Settings** | Display name, password, event settings (`is_active`, `uploads_enabled`, slug) |
| **Profile** | Event list, contact directory |

### Settings — key fields

- **Display name:** Dashboard greeting (`Good morning, …`)
- **Active event settings:** Toggle invitation access and photo uploads
- **Slug:** Short event identifier (URLs and file names)

## Guest experience

- **RSVP:** Name, email, status, exact party size (1–20), dietary requirements, and private notes
- **Photo upload:** Multiple files, HEIC support; approved photos appear in the invitation collage
- **Leave a message:** Guestbook; counts update after moderation
- **Add to calendar:** Downloads an `.ics` file

Only **approved** photos and messages appear on the public invitation page.

## Troubleshooting

| Issue | Fix |
|-------|-----|
| Stale JS/CSS loading | Hard refresh: **Ctrl+Shift+R** |
| API CORS errors | Check backend `FRONTEND_ORIGINS` |
| QR opens wrong URL on phone | Set backend `PUBLIC_BASE_URL` to LAN IP or production domain |
| Sign-in fails | Use `ADMIN_EMAIL` / `ADMIN_PASSWORD` from `.env` |
| Too many login attempts | 429 rate limit — wait one minute |

## Privacy

- Photo URLs require a valid event token or admin session
- Storage bucket credentials are never sent to the frontend
- Guest uploads go through the moderation pipeline

## Brand identity — Sakin Zarafet

Shared styling lives in `css/brand.css`: ivory `#F8F5EF`, forest green `#25463B`, sage `#A8B8A0`, rose `#B97978`, champagne `#C9AA78`, and ink `#242B27`. Headings use Cormorant Garamond; UI text uses Manrope. Load this stylesheet after `styles.css`. Event-specific envelope, seal and paper colors remain controlled by the invitation editor; minimal and celebration invitation themes remain available.

### Event-specific invitation colors

The invitation editor contains 13 color selectors for the page, headings, cover text, details, memory/photo area, count badge, buttons, countdown and footer. `palette` stores only explicit overrides on the event; an empty object restores the selected theme defaults. These settings are loaded through the public invitation API and do not alter the Luma admin brand or envelope appearance. Backend migration `20260928_0018` adds the JSON palette field on startup.

### Two-stage envelope opening

The sealed-envelope option now runs Stage 1 (sealed envelope with a hinged top flap), Stage 2 (gloved hands holding the satin ribbon and embossed gatefold), then reveals the existing invitation. Local GSAP/ScrollTrigger files drive a timeline using a modal-owned scroll container. Clicking the first seal or the second-stage bow advances to the next stage; native touch scrolling works through the same timeline. Cleanup restores invitation interaction and kills owned triggers/tweens. Reduced-motion mode uses fades without spatial transforms. Existing saved appearance colors are preserved; new events default to forest green and champagne.

The ribbon color is editable with a color picker or HEX input and persists as `ribbon_color`. The satin image keeps its texture while taking the selected tint. Hands appear only on Stage 2, pivot around their grip and have sleeves that continue out of the side edges on mobile and desktop. They grip the hanging ribbon ends from below and pull sideways. Separate knot and tail layers dissolve the bow; Stage 2 has no seal or fracture effect. Ribbon strips and loose ends are children of their respective doors and rotate with them. The cover heading has no plaque background or border. The ribbon stays within the card width while closed. Opening progress is monotonic; reverse scrolling at Stage 2 reveals the invitation. Stage 1 has a raised wax seal with a subtle double-beat pulse, disabled for reduced motion.

Browser verification: run `node scripts/verify-opening.cjs` with Playwright installed. `PLAYWRIGHT_MODULE` can specify an existing module path; `BROWSER_CHANNEL` can select an installed browser such as `msedge`. The script uses local file routes and no real account or database.

## Görsel katmanlar ve fotoğraflar

Davetiye düzenleyicisindeki “Görsel katmanlar ve fotoğraflar” alanı 12 görsele kadar JPEG/PNG/WebP yüklemeyi destekler (dosya başına 5 MB). Şeffaf PNG/WebP ön plan katmanları arka planın üzerinde gösterilir. Ön planın boyutu ve yatay/dikey konumu ayarlanabilir; birden fazla arka plan seçilirse sonuncusu kullanılır. Alt bölümlere fotoğraflar, isteğe bağlı açıklamalar, kemer/oval/Polaroid/altın çerçeveler eklenebilir. Büyüme, küçülme, hafif sallanma ve paralaks hareketleri kaydırmayı takip eder; azaltılmış hareket tercihinde devre dışıdır. Önizleme dosyaları yerel kalır; kaydetme sırasında sunucuya yüklenir.

Ön plan hizalama menüsü dokuz köşe/kenar/orta seçeneği içerir. Kenar seçimleri görselin ilgili kenarını kapak sınırına oturtur. “Elle konumlandır” mevcut yüzde ayarlarını kullanır; eski görseller bu modda korunur.

## İsteğe bağlı kâğıt ve fotoğraf sergisi

Davetiye düzenleyicisindeki “Kâğıt ve fotoğraf sergisi” alanı düz, kemer, dalgalı, doğal kenarlı ve oyuklu kâğıt kesimlerini sunar. Pamuklu/çiçek kabartmalı doku, kâğıt/yazı HEX renkleri ve kapak/detaylar/tüm bilgi alanları seçilir. Varsayılan kâğıtsız görünüm korunur.

Yüklediğiniz görselleri aynı alt bölüme yerleştirip sergiyi grid olarak seçin. Masaüstünde iki/üç, mobilde iki sütun gösterilir. Fotoğraflar çerçevesiz, kemer, oval, Polaroid, altın veya fotoğraf tabanlı Barok çerçeve kullanabilir. Tek tek fotoğraflar kaldırılabilir; sergi gizlenebilir. Bu alan yönetici tarafından seçilen etkinlik fotoğraflarıdır; misafirlerin anı albümünün gizlilik ayarlarını değiştirmez.

## Bölüm arka planları ve geçişler

Görsel katmanların konum menüsünde davetiyenin tamamı, zarf açılışı, kapak, hikâye, detaylar, anı bölümü, fotoğraf sergisi, geri sayım ve alt bilgi için arka plan seçilebilir. Her alanda son atanan görsel kullanılır. “Alanı kapla”, “Görselin tamamını göster” ve “Doku olarak tekrarla” seçenekleri vardır. Tam davetiye arka planında bölümlerin varsayılan düz renk zeminleri saydamlaşır; tek bölüm görseli varsa kendi görseli görünür. Ön plan görselleri bağımsızdır.

“Kâğıt ve fotoğraf sergisi” altında isteğe bağlı yırtık/dalgalı geçiş kâğıdı, geçiş alanı ve HEX rengi seçilir. Kapak/hikâye/detay/sergi sonrasına, anı bölümünün önüne veya tüm bölüm aralarına uygulanabilir. Kapatmak yüklenen fotoğrafları silmez.

Paralaks, tam davetiye ve bölüm arka planlarında kırpılmış bağımsız yüzey üzerinde çalışır; ayrı kapak görseli seçilmemişse kapak da bu ortak yüzeyi gösterir; ikinci kapak kopyası oluşturulmaz. Hareket azaltma tercihi açık olduğunda animasyon uygulanmaz. Zarf açılışının arka planı statiktir; açılışın kendi animasyonu ayrı çalışır.

## Sticker ve mobil düzenleme önizlemesi

Şeffaf PNG/WebP stickerlar kapak, hikâye, detaylar, anı bölümü, sergi ve geri sayım üzerine yerleştirilebilir. Boyut yüzde 5–100 arasında ayarlanır; köşe/kenar/orta veya serbest konum kullanılır. Ortadan sağa/sola, soldan sağa/sağdan sola ve açılarak sağa/sola kayma seçenekleri gerçek kaydırmayı takip eder; azaltılmış hareket tercihinde sabit görünür.

İlk zarfın dış zemin rengi “Davetiye görünümü” altında renk seçici ve HEX alanından bağımsız ayarlanır. HEX boşsa varsayılan renk kullanılır. Açılışa görsel arka plan atanmışsa görsel, bu rengin üzerinde yer alır.

Düzenleyicinin sağındaki canlı mobil yerleşim önizlemesi, kaydedilmemiş dosyaları ve ayarları 390 px mobil tuvalde gösterir. Değişen görselin bölümünü takip eder; masaüstünde sayfa kayarken sağda sticky kalır; küçük ekranlarda Görsel katmanlar ve fotoğraflar bölümünün hemen üstüne taşınır ve kompakt görünür. Önizleme yükleme veya kayıt isteği göndermez. Kaydırma animasyonları tam “Canlı önizleme” ekranında denenir.

### Mobil açılış önizlemesi ve görünüm

Mobil önizlemenin “Gösterilen alan” seçicisinden ilk mühürlü zarf veya ikinci kurdeleli kapak seçilebilir. Renkler ve etkinlik bilgileri kaydetmeden güncellenir; tam hareketli akış Canlı önizleme ile denenir. Açılışta 24 px kaydırma hareketi geçişi başlatır; sahne ekranın tamamını kaplar ve geri kaydırma kapanışa yol açmaz.

Davetiye görünümündeki Buton köşe yuvarlaklığı alanı varsayılan, 0/8/16 px, kapsül veya özel 0–999 px değerini destekler. Etkinlik sunum ayarlarına kaydedilir. Adres, ulaşım, iletişim ve program bilgileri masaüstünde iki sütuna, telefonda tek sütuna yerleşir.

Çerçeve sergisinde 2, 3 veya 4 sütun seçilebilir; seçilen sütun sayısı mobilde de korunur. Dört sütunda dört görsel aynı satırda yer alır.

Asimetrik sergi, her dört fotoğrafı iki satırda 1/4–3/4 ve 3/4–1/4 oranında yerleştirir. Mobilde aynı düzen korunur; fotoğraf sırası görsel katman düzenleyicisinden değiştirilebilir.

Davetiye görünümü → Kurdeleyi açan eller alanında beyaz eldiven veya Halloween cadı elleri seçilebilir. Kullanıcının şeffaf witch_hand.png görseli yerel varlık olarak kullanılır; seçim etkinliğin sunum ayarlarına kaydedilir ve kurdeleli kapak önizlemesinde görünür.

İlk zarf mührü kullanıcının sağladığı stamp.png fotoğrafını kullanır. Mühür üzerindeki yazı alanı orijinal yazısız fotoğraf veya isimlerden türetilen baş harfler arasında seçilir; renk seçicisi baş harf rengini belirler. Kalp atışı animasyonu açılış başlayınca durur; azaltılmış hareket tercihinde çalışmaz.

Görsel katman düzenleyicisindeki hazır Halloween stickerları kullanıcı tarafından sağlanan dört PNG görselidir. Seçim düzenlenebilir taslak oluşturur; Kaydet sırasında normal görsel yükleme yoluyla etkinliğe ait varlık olarak saklanır. Stickerlarda kaydırmayla dönme, dönerek kaybolma ve opaklığı azalarak kaybolma efektleri bulunur; hareketi azalt tercihi animasyonları kapatır.
